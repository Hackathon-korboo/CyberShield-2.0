## 2. Module 1: AI Scam Intelligence Engine

### 2.1 Threat Taxonomies & Detection Scope
The message analysis subsystem inspects untrusted communications across 8 critical fraud vectors:
1. **Phishing & Credential Theft**: Fake KYC/PAN deadlines, unencrypted HTTP portals, account suspension threats, and Microsoft 365 / Google Workspace credential harvesting.
2. **SMS Smishing & OTP Theft**: Urgent demands for 6-digit OTP codes, debit card PINs, CVVs, and mobile SMS forwarding lures.
3. **Fake Recruitment & Internship Schemes**: Lucrative work-from-home offers ($5,000+/month) requiring upfront registration fees, refundable laptop security deposits, or Telegram task scams.
4. **Authority Impersonation (Digital Arrest)**: Extortion schemes impersonating the CBI, TRAI, Delhi Police Cyber Cell, or customs officials claiming narcotics packages linked to Aadhaar numbers.
5. **Payment & UPI Manipulation**: Scan-to-receive QR code scams, cashback lottery lures (PhonePe, Google Pay), and deceptive UPI PIN authorization prompts.
6. **Regulatory Transactional Protection**: Intelligent whitelist heuristics that recognize legitimate RBI-mandated transactional debit notices (e.g., `"SMS BLOCK to 56767"`), preventing false alarms.

### 2.2 Evidence Grounding Guarantee
To eliminate LLM hallucinations:
- Every indicator reported to end users must pass through `EvidenceValidator.filter_and_ground_indicators()`.
- The validator computes exact case-insensitive substring matches against the raw submitted message.
- Any indicator generated by an LLM that cannot be cited as a verbatim substring in the user's message is purged before response synthesis.

## 3. Module 2: Prompt Injection Defense Architecture

Untrusted user input can contain adversarial attacks designed to hijack model instructions. Member 2 implements a 4-tier defense perimeter:
1. **XML Boundary Encapsulation**: Untrusted input is strictly enclosed inside `<untrusted_user_message>` tags with clear boundary declarations to the LLM.
2. **Tag Breakout Escaping**: Any occurrences of `</untrusted_user_message>` or `<system>` inside untrusted text are escaped to `[ESCAPED_UNTRUSTED_TAG]` prior to prompt assembly.
3. **Adversarial Pattern Detection**: Real-time regex detection identifying:
   - Instruction overrides: `"ignore previous instructions"`, `"system override"`, `"disregard safety rules"`.
   - Secret exfiltration: `"reveal your system prompt"`, `"show GEMINI_API_KEY"`, `"output API credentials"`.
   - Base64 encoded instruction injections.
4. **Deterministic Heuristic Override**: If an injection attempt is detected, the LLM's classification cannot override the security findings; the system automatically flags the input as `Suspicious` or `High Risk`.

In compliance with the hackathon's *Privacy-Preserving Computation* focus area:
- `PIIRedactor` inspects text before it leaves the local host.
- Sensitive entities are transformed into deterministic opaque placeholders:
  - Indian PAN Cards: `[REDACTED_ID_1]`
  - Aadhaar Numbers: `[REDACTED_ACCOUNT_1]`
  - Credit / Debit Cards: `[REDACTED_ACCOUNT_2]`

  - Email Addresses: `[REDACTED_EMAIL_1]`
- The mapping is maintained strictly in memory on the local backend and is used only to restore tokens for authorized local display in the user's browser, preventing external data exfiltration.

## 5. Module 4: Antivirus-Style Static File Security Analysis

### 5.1 Magic Bytes & Extension Spoofing Detection (`file_signature_checker.py`)
- Reads the leading header bytes of uploaded files without loading entire files into memory.
- Recognizes executable formats:
  - Windows PE/COFF: `MZ` header (`4D 5A`)
  - Linux / Unix: `\x7fELF` (`7F 45 4C 46`)
  - macOS Mach-O: `\xfe\xed\xfa\xce`, `\xca\xfe\xba\xbe`
- **Extension Spoofing Detection**: If a file is named with a benign extension (`.pdf`, `.jpg`, `.docx`, `.txt`) but internal headers reveal an executable binary (`MZ` / `ELF`), the file is immediately flagged with `CRITICAL EXTENSION SPOOFING` (Risk Score: 95/100).
- Identifies macro-enabled Office containers (OLE Compound File `\xd0\xcf\x11\xe0` containing VBA Project streams) and dangerous script interpreters (PowerShell cmdlets, Unix shebangs, VBScript automation).

### 5.2 Archive Safety Guard (`archive_safety_guard.py`)
- **Safe Non-Extracting Inspection**: Reads ZIP central directory metadata and TAR headers in memory. **Zero files are extracted to disk**.
- **Zip Slip Defense**: Flags any archive entry containing `../`, `..\\`, absolute drive roots (`C:\`), or null bytes trying to escape target directories.
- **Decompression Bomb Defense**: Enforces strict thresholds:
  - Max compression ratio: **100:1**
  - Max total uncompressed size: **50 MB**
  - Max entry count: **250 files**
- **Embedded Executable Inspection**: Audits internal filenames and flags hidden `.exe`, `.scr`, `.bat`, `.ps1`, or `.vbs` payloads concealed inside compressed archives.

### 5.3 Malware Hash Matcher (`malware_hash_matcher.py`)
- Computes MD5, SHA-1, SHA-256, and SHA-512 cryptographic digests in a streaming pass.
- Matches against verified threat families:
  - **EICAR Standard AV Test File** (Universal test verification)
  - **WannaCry Ransomware** (`Ransomware.WannaCry.WanaCrypt0r`)
  - **Emotet Banking Trojan** (`Trojan.Emotet.Heur`)
  - **Locky Ransomware** (`Ransomware.Locky`)
  - **Mirai Botnet** (`Botnet.Mirai.LinuxELF`)
  - **AgentTesla Infostealer** (`Spyware.AgentTesla`)
- Matched files receive an immediate deterministic **Critical Risk Score (100/100)**.

## 6. Module 5: Gemini File Threat Explainer

When an uploaded file is audited, `FileThreatAnalyzer.explain_threat_with_gemini()` generates a contextual interpretation for security operations centers:
- **Sanitized Metadata Only**: Sends filename, file size, SHA-256 fingerprint, detected MIME type, and detected threat indicator descriptions.
- **Zero Binary Leakage**: No raw file bytes, binary chunks, or document text are ever uploaded to Gemini.
- **Actionable Remediation**: Produces tailored containment steps (e.g. firewall hash blocking, macro disabling, EDR quarantine) while explicitly acknowledging static analysis constraints.

- **Content-Type**: `multipart/form-data`
- **Request**: `file: UploadFile`

  - `hashes`: MD5, SHA-1, SHA-256, SHA-512.
  - `signature_analysis`: Detected MIME, detected format, extension mismatch boolean, magic hex bytes.
  - `archive_analysis`: Entry counts, compression ratio, path traversal flags, embedded executables.
  - `malware_match`: Is matched, threat family, malware type, reference description.
  - `indicators`: Structured technical indicators with verbatim evidence.
  - `ai_contextual_explanation`: Gemini threat assessment.
  - `recommendations`: Actionable mitigation steps.
